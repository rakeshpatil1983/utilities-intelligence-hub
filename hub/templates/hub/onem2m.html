oneM2M · data inflow and interworking

The hub is a oneM2M Application Entity. It registers in any oneM2M CSE (ACME, OM2M, Mobius …) over the standard HTTP binding, publishes every device's health, issues and prediction as contentInstances, and receives field readings through CSE subscriptions — so other oneM2M applications can use the hub's intelligence, and devices on a oneM2M platform can feed it.

Connect a CSE

  1. Run a CSE, e.g. ACME: http://127.0.0.1:8080/cse-in (OM2M: http://host:8080/~/in-cse/in-name).
  2. In .env: ONEM2M_CSE, optional ONEM2M_ORIGIN, and ONEM2M_POA = this hub's /onem2m/notify URL.
  3. manage.py onem2m_push — creates the AE and containers, posts one contentInstance per device (re-run on a schedule).
  4. manage.py onem2m_push --subscribe <path> — subscribes the hub to a field gateway's container; its readings arrive below.

Primitives: X-M2M-Origin, X-M2M-RI, X-M2M-RVI {{ "3" }}, Content-Type application/json;ty=2 (AE) / 3 (container) / 4 (contentInstance) / 23 (subscription). The status documents are also at /api/v1/onem2m.
